## Main gaps and threats to validity

1. **Three responses are smoke tests, not reliability measurements.** Two chat responses and one proactive correction are verified for this pass; they are not billable-unit counts. No further generations. The welcome example remains separate pre-existing content.
2. **Reload persistence is narrow positive evidence.** Note/title, mode, persona, both chat exchanges and resolved-thread state survived one same-profile/account reload (EXP-08). Offline, restart, multi-device, conflict and crash consistency remain unknown. Purpose/folder were saved/created later and not reload-tested.
3. **Mode behavior has a limited positive contrast, not a complete contract.** Quiet setup produced no new margin thread; feedback appeared within the subsequent 15-second proactive observation wait. Mode-switch versus append initiation, exact latency/debounce, hidden transmissions and metering remain unknown.
4. **Anchors still lack drift tests.** Returned quote and exported correction match earlier photosynthesis text, not necessarily newest dry-mass text. Exact live range, insertions, duplicates, deletion and revision races are untested. Resolve hid the thread; later chat count/export/reload establish some retention, not interactive reopen or backend erasure guarantees.
5. **Persistent chat is not complete context retrieval.** Both exchanges remained through reload/persona change and left the note unchanged. Marker lookup, freshness, actual thread-text inclusion and cross-note isolation remain untested. A header counting one thread is not evidence that its text was sent to the model.
6. **Persona lifecycle works in this account; causal effect is unproven.** Creation/edit/save/select and persisted selection are verified. The diagnostic question is consistent with both persona and explicit prompt; no controlled A/B was run. Thread reply, Dismiss, full-screen, Copy and Make a note remain unexercised.
7. **Media/input gaps remain.** Pre-existing drawing and enlargement control do not establish new visual generation. Spoken notes are advertised, not recorded/tested. Image-related request fields do not establish an upload affordance, accepted formats, extraction or OCR. No files/audio were supplied.
8. **Commercial/model claims are not backend guarantees.** Free billing and dated pricing state one-time nonrefilling allowance and same named model across plans. Exact final balance, charge units, paid behavior and actual provider/model identity are unverified. Never treat the advertised model name as an independently usable API model ID.
9. **One free-account session is not a reliability study.** Short windows, UI experiments, stochastic output, and changing product versions limit generalization. Record once-observed outcomes honestly; do not spend allowance on artificial replication.
10. **Privacy is not established by absence of visible activity.** Sharing audience, transmission, training/retention, deletion, telemetry, and cancellation billing remain unknown. User text and secrets are never research fixtures.
11. **Live failure injection is neither necessary nor authorized.** Offline/conflict/error/retry/cancellation races should be tested deterministically in the independent local harness, not by stressing Riddled.
12. **Transport/UI effects must not be conflated.** Two `/api/riddled` POSTs returned HTTP 200 `application/json`; network streaming was not observed. UI word reveal is compatible with client-side presentation and cannot prove streaming or rule out other transport behavior elsewhere. HTTP 200 alone is not a correctness, billing, or retention guarantee.
13. **REA limitations preclude absence claims.** WS passive snapshots succeeded, network windows missed requests, and bundle analysis examined 13 sources with one timeout and no route candidates. The HTTP-only scenario discovery requirement did not match the WS browser endpoint (`/json/version` returned 404), so no scenario executed. These are capture/tooling limitations, not evidence that routes or product behaviors are absent.
14. **Export is useful but incomplete portability evidence.** One actual Markdown includes body and resolved feedback, but not note-chat, persona instructions or explicit resolution metadata (EXP-07). Purpose was absent but saved later, so its exportability was not tested. PDF/Word, no-riddles variant, clipboard and round-trip remain unknown.
15. **Organization/search/accessibility scope is limited.** Folder create/drag/collapse count 1 works in the reported state; reload/rename/delete were not tested. Title palette matching in DOM is positive evidence, while omitted accessible descendants limit snapshot-based conclusions; this is not a complete assistive-technology audit. Body-marker search is inconclusive, not absent.
16. **Research scope is not a feature wishlist.** Proposed local safety behavior can be justified without attributing it to Riddled. Quiz/flashcard/progress systems remain unrelated proposals unless later evidence supports attribution.
